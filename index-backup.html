🔄 Private Fork Workflow

Setup: Zwei Remotes

origin Dein privates Repo 
bastiantonn/everything-claude-code

Für deine privaten Anpassungen

upstream Original public Repo 
affaan-m/everything-claude-code

Für Updates vom Original

Eigene Änderungen pushen

git add .
git commit -m "feat: Meine Anpassung"
git push origin main

Geht zu DEINEM private repo

Updates vom Original holen

git fetch upstream
git merge upstream/main
git push origin main

Holt Updates, merged sie, pushed zu dir

💡 Conflict-Free Strategy

Erstelle eigene Komponenten in separaten Ordnern: 

my-agents/       ← Deine custom agents
my-commands/     ← Deine custom commands
my-skills/       ← Deine custom skills
my-rules/        ← Deine custom rules

Vorteil: Zero Merge Conflicts! Original-Dateien bleiben unberührt.

✨ Best Practices

✅ DO

  • • Regelmäßig upstream updates holen (wöchentlich)
  • • Eigene Komponenten in my-* Ordner
  • • Projekt-Regeln in .claude/rules/
  • • Context Window im Blick behalten (< 80%)
  • • MCPs aufräumen (< 10 aktiv)

❌ DON'T

  • • Secrets committen (nutze .gitignore)
  • • Original-Dateien editieren (besser: kopieren)
  • • Alle MCPs gleichzeitig aktivieren
  • • Context Window ignorieren
  • • Ungetestete Features deployen
