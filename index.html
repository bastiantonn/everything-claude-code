export function useDebounce(
  value: T,
  delay: number
): T {
  const [debounced, setDebounced] =
    useState(value)

  useEffect(() => {
    const handler = setTimeout(
      () => setDebounced(value),
      delay
    )
    return () => clearTimeout(handler)
  }, [value, delay])

  return debounced
}

🔌 MCPs (Model Context Protocol)

MCPs sind Plugins, die Claude Code zusätzliche Tools geben (GitHub, Databases, Deployment, etc.). ABER: Sie verbrauchen Context Window! Smart nutzen!

Was sind MCPs?

Model Context Protocol (MCP) ist ein Standard für Plugins, die Claude Code neue Fähigkeiten geben - ähnlich wie VS Code Extensions.

Vorteile:

  • Zugriff auf externe Services (GitHub, Supabase)
  • Vereinfacht komplexe Workflows
  • Standardisiert & wiederverwendbar

Nachteile (WICHTIG!):

  • Verbraucht Context Window (pro MCP ~5-10%)
  • Höherer Token-Usage = höhere Kosten
  • Kann Performance beeinträchtigen

⚠️ Regel:

Nutze maximal 5-7 MCPs gleichzeitig. Mehr = Context Window Probleme!

Verfügbare MCPs

🐙 GitHub MCP

Create PRs, Issues, Comments, View Repos

Context: ~8%

🗄️ Supabase MCP

Database Queries, RLS, Migrations

Context: ~6%

▲ Vercel MCP

Deploy, Logs, Environment Variables

Context: ~5%

🚂 Railway MCP

Deploy Services, Databases, Logs

Context: ~5%

🔍 Web Search MCP

Search the web for current info

Context: ~4%

🌐 Browser MCP

Navigate, Click, Fill Forms

Context: ~7%

⚠️ Context Window Management (KRITISCH!)

Das Problem:

Jeder MCP verbraucht Context Window durch Tool-Definitionen, Schemas und Dokumentation. Mit 10+ MCPs hast du nur noch 50-60% Context für deine eigentliche Arbeit!

Die Lösung: CLI + Skills statt MCPs

Die meisten Platforms haben bereits CLIs. Nutze diese direkt!

❌ Mit MCP (verbraucht Context):

// GitHub MCP geladen (8% Context)
// Supabase MCP geladen (6% Context)
// Vercel MCP geladen (5% Context)

// Command: /supabase-migrate

// Command: /deploy
